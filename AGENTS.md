# Home Run Simulator

Build a satisfying arcade batting loop grounded in deterministic physics. Stages 1-5, Stage 6A economy/Power, Stage 6A.1 skip/preview and Stage 6B stadium progression are implemented. Stage 6C adds rebirths and permanent server-owned progression; session counters remain separate. Stage 7A adds free roam, explicit handed box entry/exit, shared menu input and procedural pitcher/audio presentation. The implementation is the source of truth when older documentation disagrees.

## Architecture and constraints

- Rojo maps `src/shared`, `src/server`, and `src/client`. Preserve `default.project.json` and Studio-managed `Workspace.Stadium` assets unless the task requires a change.
- Pitching uses server-authoritative precomputed 240 Hz trajectories. Beginner pitches are already 50–55 mph; preserve pitching speeds, solver, timing and replication.
- `SwingModel` positions the sweet spot on the mouse aim plane and provides analytic bat poses. `BatCollision` sweeps two capsules using conservative advancement. Keep the rendered and collision poses identical.
- `SwingValidator` validates intent, timestamps, aim bounds, rate limits and one swing per pitch. The server resolves against its stored trajectory; never trust client positions or outcomes.
- `ContactQuality` measures geometry and grades contact. Labels describe outcomes; never use labels to assign launch angles, power or distance.
- `BattedBall.computeLaunch` and `ImpactModel` are shared by client prediction and server authority. Flight uses fixed-step 120 Hz RK4 with gravity, drag, Magnus lift and spin decay. Keep nearby inputs continuous and results deterministic.
- `LandingDetector` performs authoritative first-impact sweeps. Flat-field carry projections are benchmarks, not stadium landing outcomes.
- `CameraDirector`, `HitPresentation`, and client effects/HUD own Stage 4 presentation. Preserve their behavior, animations, aiming responsiveness and networking when tuning contact.
- `GameplayServer` integrates validated server events with pure `SessionStats`, `RecordRules` and `ReturnGate`. Records use confirmed, non-provisional fair ground carry only. All accepted contacts remain successful hits. Keep snapshot versions and hit/assignment deduplication.
- Production hit completion waits for validated camera readiness; `HitLifecycle`'s fixed hold is a legacy fallback. No client message may resolve/cancel a flight, report distance, or unlock a lane before server resolution and the minimum return interval.
- SI units inside impact/flight; world studs at Roblox boundaries. Use the existing `Units`/`FieldFrame` conversions.

## Stage 6B world contract

- `Worlds/WorldConfig` owns stable IDs (`rookie`, `power`, `sky`), origins, rotations, lane counts, landing extents and free unlock thresholds (475 / 1,750 ft). Stage 6A economy and Power formulas stay unchanged.
- `WorldRegistry` owns ONLY runtime `Workspace.GeneratedWorlds`. `Workspace.Stadium` and `Workspace.GameplayMarkers` remain Studio-managed. Do not map generated models into Rojo or overwrite the original place with a CLI build.
- `Construction` and `StadiumBuilder` generate bounded, repeatable geometry. Power and Sky each have four lanes. Rookie uses the existing lanes and a separate catchment surrounding its measured bounding box, below plate level. No original geometry or marker is moved.
- Marker coordinates are world studs. New lane IDs include the world (`power/Lane1`); original lane IDs are preserved. Home, pitcher, batter, foul poles and bases are marker-relative; the existing solvers and SI conversions remain authoritative.
- `WorldCollision` uses explicit per-world inclusion lists. Visible architecture and ground collide; clouds, markers, markings and light trim do not. Global Terrain, unrelated world parts and other worlds cannot terminate a hit. Add intended Rookie collision assets under its Stadium; do not silently rely on unrelated Workspace geometry.
- Unlock qualification uses the same valid, confirmed, non-provisional fair ground carry requirements as records/rewards, within existing numeric limits. Never use a projection or client distance. Snapshots are schema 3, versioned and detached; pending hit deduplication remains intact.
- Stage 7A `BatterService.travel` is a non-yielding progression/placement transaction. Reject locked/unknown worlds, stale/replayed/spam requests, missing characters, active hits and incomplete camera return. Travel never cancels an authoritative flight. Stop only the incoming pitch, release the old gate, preserve progression/stats and place in destination free roam. Occupied batting lanes do not prevent exploration/travel. The next box entry requires fresh character/camera readiness.
- Stage 7A supersedes automatic assignment/FIFO: join/reset/travel keep the selected world and use free roam; only explicit nearby box entry reserves a lane. Disconnect cleans ownership. Late swing intent carries lane ID and must postdate assignment; sequence/cooldown guards survive travel/re-entry while per-pitch swing use is cleared.
- Client World UI closes/suppresses batting intent while open; lane changes clear predictions, effects, preview and camera context. Atmosphere changes are local. Generated worlds use PersistentPerPlayer streaming, retained only for the player's current world so long cinematic flights retain geometry.
- The flight solver remains 120 Hz, bounded to 30 seconds / 3,600 steps / 10 km horizontal range. New ground extends 6,500 studs forward; paths outside supported geometry resolve explicit OUT OF RANGE/NoImpact with no carry reward or unlock. Do not fabricate distances or remove limits.
- Stage 6C persists stable unlock IDs, selected world, qualifying best, coins, Power, rebirths and lifetime milestones through the existing progression reducer and profile manager. Validate saved IDs and always restore Rookie unlocked. Never serialize runtime hit IDs, request clocks, assignments or deduplication state. No pets, monetization or unrelated progression.
- Run all CLI checks, both baseline balance analyses and `--worlds docs/stage6b-worlds.json`. Studio-only construction/collision tests run through the existing runner. `tools/stage6b-multiplayer.server.luau` is an opt-in temporary fixture, never production/Rojo mapped. Its seeded qualification checks adapters, not earned gameplay.
- README's Stage 7A section is the current mode integration/playtest checklist; Stage 6C remains the persistence contract. Never infer visual quality, camera feel or production multiplayer performance from CLI tests alone.

## Stage 6C profile contract

- `PlayerProgression` remains the single non-yielding progression reducer. `ProfileStore.mutate/resolve` gates persistent mutations by a successfully acquired, unexpired session lease. Purchases include the expected rebirth epoch; rebirths include expected count/version and independent sequence/cooldown guards. Never add client data or distance-report endpoints.
- Rebirth requirement is `8 + completedRebirths`, with 12 supported rebirths. Permanent strength is `1 + 0.25 * rebirths`; total launch strength is the Stage 5A baseline times `1.12^PowerLevel` times that permanent bonus, applied once. Base rewards/prices are unchanged. Reset only coins and Power; preserve worlds, selected world, qualifying best, milestones and lifetime totals. Capture level, version and rebirth count at contact; never change existing flights.
- Storage schema 1 contains coins, earnedCoins, Power, rebirths, stable world IDs, selected world, best, milestones and bounded lifetime fair-carry totals. Multipliers/highest-world are derived. Networking snapshot schema 3 is separate. `PlayerData` defaults, migrates version 0, sanitizes fields and fails closed for future schemas or malformed root/envelope/lease data.
- `Persistence/ProfileStore` uses atomic UpdateAsync for data plus GUID ownership, a 180-second lease, staggered ~60-second renew/save, a 15-second mutation safety margin, budget checks and four bounded retries with exponential backoff/jitter. Ownership is verified inside each transform; stale writers may not reacquire in save. Per-profile operations serialize; mutations during a save retain a dirty revision. PlayerRemoving and BindToClose freeze mutations and attempt bounded final saves/releases (25-second close window).
- Load failure installs no progression state and never saves defaults. Save failure pauses progression; validated pending resolutions queue until ownership renewal, then credit once. Lost ownership requires rejoin. Never label failed writes as saved. Underlying Roblox calls cannot be forcibly canceled; document crash rollback and live-service limitations accurately.
- Studio defaults to Mock/New. Returning, LoadFailure and SaveFailure scenarios are mock-only; real Studio testing must explicitly use DataStore mode and the separate DEV namespace. Restore Mock/New and normal intervals after testing. Never test production player data destructively.
- Run all prior checks plus `--rebirths docs/stage6c-rebirths.json`, the two-level comparison `--rebirths-baseline`, persistence failure/lease specs and Studio tests where available. Preserve the original physics/economy reports; compare only documented metadata/timing differences. Mock tests do not establish live DataStore reliability.

## Stage 7A mode contract

- Join/respawn/travel use normal Roblox third-person movement, jumping, cursor and camera in the selected unlocked world. Free roam consumes no batting capacity and starts no pitches.
- Native E prompt entry independently validates profile/lease readiness, living character, selected world, valid box, <=6-stud root-to-ground distance, 0.35-second gap and lane capacity. Both hand boxes share one reservation. No swing packet selects handedness.
- RightBatter/RightBatterMarker/BatterMarkerRight means right-handed on third-base side (-lane.right); Left equivalents mean first-base side (+lane.right). Use marker bottom centers; validate side and <=2.5 m distance, otherwise warn/use +/-0.95 m plate-relative fallbacks. Do not move Rookie markers/outlines. Runtime prompts/outlines stay under GeneratedWorlds.
- Runtime handedness is per-lane geometry, shared by SwingModel/CharacterPose, collision and FieldFrame; never mutate global config for a batter. Legacy default remains for benchmarks. Both cosmetic raises point up. Preserve Active rendered/collision identity, early/late spray, all physics/timing and balance.
- E aborts only incoming pitches. Confirmed flying/landing/returning hits queue departure: stop new swings/pitches, retain ownership, credit once and wait for validated camera readiness/minimum return interval before releasing. Independent exit sequence and expected lane/epoch reject replay, spam and stale/non-owner requests.
- Death/reset restores free-roam presentation/movement while retaining only a pending result reservation. The respawned character acknowledges actual restored camera readiness through the existing gate after resolution. Disconnect keeps abandoned-hit cleanup. Travel cannot cancel authority.
- BattingMovement restores captured speed, both jump settings/mode, AutoRotate and anchoring; CharacterGrip restores joints/animations. BattingCamera restores Custom/current Humanoid/captured FOV. Never strand a player in Scriptable camera or anchored stance.
- InputCoordinator alone owns batting/menu MouseIconEnabled/MouseBehavior. Major panels/CoreGui/text focus suppress swings/reticle. Closing clicks have a 0.15-second guard; GUI hit surfaces block swings independently of gameProcessedEvent. Apply pointer policy after Roblox camera to handle shift-lock. Preserve G/Space/F6/F7.
- PitcherMotion/PitcherVisualController follow existing windup/release timestamps and jittered release point. One ball follows the throwing hand before the unchanged trajectory. No invented animation IDs, extra release ball, altered physics or per-frame remote stream.
- PresentationConfig.Sounds/GameAudio own bounded cue mixing and async fallback. Flight loop is optional/off until a suitable licensed asset is supplied. Use verified built-ins or licensed accessible assets, never invented IDs or unsupported sound-quality claims.
- Run all prior checks/analyses plus BattingMode specs and fresh Studio tests. Stage7A multiplayer fixture is opt-in, temporary, Mock/New only and never mapped/shipped. The preserved Stage6B fixture expects obsolete automatic/FIFO behavior. Distinguish seeded synthetic contacts from earned gameplay; remove temporary Studio scripts/status attributes after tests.
